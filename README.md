# Spheres Character Sheet

A character sheet for Pathfinder 1e with Spheres of Power, Might and Guile (Drop Dead Studios). It works out
hit points, AC, saves, DCs, spell points, talents, skills and attacks from the character's data, and has example
characters, share links and parties. It is live at https://spheres-character-sheet.web.app. A fan project, not
affiliated with or endorsed by Drop Dead Studios or Paizo.

## How it is built

- The whole sheet is one self-contained page, `public/index.html`: HTML, one CSS block and the scripts. There is no
  build step and no `package.json`.
- `public/talents/*.json` hold the wiki text for talents and drawbacks, loaded on demand. They are generated by
  `tools/build-talents.py` from the offline wiki bundle (`SoP-Claude-Bundles`); normal sheet changes don't touch them.
- `public/classes/*.json` hold the Spheres classes' features by level, with their wiki text and choice lists, loaded when
  a class levels up. They are generated by `tools/build-classes.py` from the same bundle.
- Hosting and the database are Firebase (project `spheres-character-sheet`); `firestore.rules` holds the database rules.

## Running it locally

Open `public/index.html` in a browser, or serve `public/` with any static server (for example
`python3 -m http.server -d public`). The wiki descriptions need `public/talents/` next to the page.

## Tests

They live in `tests/`, are never deployed, and use Node. The browser ones need Playwright. Counts and the last full
run are in the notes (`SPHERES_SHEET_NOTES.md`).

- `node tests/engine-check.js`: the rules engine directly through a read-only handle, no clicking (about 2 seconds).
- `node tests/check.js`: opens the page, loads both example characters, clicks through the sheet and compares with
  hand-worked values (about 95 seconds).
- `node tests/fuzz-check.js`: loads the examples with script payloads in their data and opens every tab, failing if
  any markup or script gets through (about a minute).
- `node tests/talents-check.js`: the description files in `public/talents/` and the class files in `public/classes/` (no browser, a second).
- `node tests/config-check.js`: `firebase.json` against `firebase.emulators.json`, and the workflow file's shape (no installs).
- `node tests/csp-check.js`: the script policy from `tools/csp.js` against the page (needs the `firebase` npm package).
- `rules-check.js`, `party-check.js`, `save-check.js`: the database rules, share links and parties, and how often the
  sheet saves. They run in the Firebase emulators and need Java; the exact commands are in each file's header.

## Deploys

A push or merge to `main` runs `.github/workflows/deploy.yml`: every check runs, and only if all pass the deploy job
publishes `firestore.rules` and then deploys Firebase Hosting. Pull requests run the checks only. A failed check
leaves the live site unchanged. Only `public/` is deployed (see `firebase.json`), so this README, `tests/` and
`tools/` are not.

## Tools

- `tools/build-talents.py <bundle folder>`: rebuilds `public/talents/` from the offline wiki bundle.
- `tools/build-classes.py <bundle folder>`: rebuilds `public/classes/` (class features) from the offline wiki bundle.
- `tools/verify-classes.py <bundle folder>`: compares the class list (talent progressions, hit die, BAB, saves, skill ranks, class skills) with the wiki bundle.
- `tools/csp.js`: works out the script policy (Content-Security-Policy) for `public/index.html`; the deploy writes it into `firebase.json`.

## Working on index.html

It is about 1.3 MB with some lines hundreds of thousands of characters long. Three rules:

1. Never load the whole file into an editor or an assistant. Use `grep -n ... | cut -c1-600` to find the place, then read
   a small range of lines. Skip the huge single-line data blocks near the top of the script.
2. Changing a saved field means converting old characters in `sanitizeChar`; saves from before the change must still load.
3. Every piece of text written into HTML goes through `esc()`.
